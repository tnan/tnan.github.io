0. ARCHITECTURE & FILE STRUCTURE (NON‑NEGOTIABLE)

You will create exactly two files at the same folder level on the server:

index.html — A single, self‑contained file exceeding 10,000 lines of HTML/CSS/JS. No external CDN dependencies (all libraries must be inlined or zero‑dependency vanilla JS/CSS). The app runs entirely client‑side.
data.json — The external data persistence file. The app reads this file on load via fetch('./data.json') and writes back to it via a simulated save mechanism (since client‑side JS cannot overwrite server files directly, the app must offer:
Auto‑download of updated data.json on every significant change (triggered via an anchor[download] blob).
Manual "Save to Server" button that generates the JSON blob and prompts the user to replace the server file.
localStorage hybrid mode: If data.json is missing or the fetch fails, bootstrap from localStorage and continue operating; on save, update both localStorage and offer the JSON download.

2.1 Universal Searchable Dropdowns (CRITICAL)

Every <select>, every account picker, every customer/vendor/product dropdown, every currency selector, every tax rate picker, every project/class/location dropdown — if the list has >5 items, it MUST be replaced with a custom searchable combobox.

Behavioral Specification:

Clicking the field opens a floating panel (not native <select>).
Panel contains:
Search input at the top, sticky, auto‑focused, placeholder "Search…"
Virtual scroll list (if >50 items) for performance.
Group headers if applicable (e.g., "Assets", "Liabilities").
Keyboard navigation:
↑/↓ arrows move highlight.
Enter selects.
Escape closes.
Tab blurs and closes, keeping current selection.
Filtering: Fuzzy search using fuse.js-like algorithm (implement lightweight version: split query by space, match each token against option text; score by token order proximity). Highlight matched characters in bold with color: var(--accent-primary).
Recent selections: Show last 5 picked items at top under "Recent" when search is empty.
Create new: If no match and user has permission, last option is + Create "Query" which opens the quick‑add modal.
Multi‑select variant: Checkboxes inside dropdown, chips appear in input field, × to remove.
Mobile: Full‑screen bottom sheet version of the dropdown.

5. STORAGE, PERFORMANCE & OFFLINE ARCHITECTURE

5.1 Storage Strategy

Primary: localStorage for active company data (fast reads).
Overflow: If data exceeds 5MB, shard into localStorage keys by entity type (omnibook_accounts, omnibook_transactions, etc.) using a manifest key omnibook_manifest that tracks all keys.
Large Payloads: Base64 attachments and audit logs go into IndexedDB via a lightweight promise wrapper (openDB, get, put, delete). Use object stores: attachments, auditLogs, exports.
External File: On boot, attempt fetch('./data.json'). If success, hydrate state. If fail, use localStorage/IndexedDB. Provide a prominent "Sync to File" button in settings that serializes everything to a Blob and triggers download.
5.2 Performance Requirements

Target: First contentful paint < 1.5s on mid‑range mobile.
Bundle: Since everything is inline, minify all CSS and JS (no external HTTP requests except the optional data.json).
List Virtualization: Any list with >100 items (transactions, products, audit log) must use virtual scrolling.
Lazy Loading: Load report data only when tab is activated. Preload dashboard only.
Computed Caching: Cache currentBalance per account, contactBalance, inventoryValue in a computedCache object keyed by entityId + dirtyTimestamp. Invalidate on relevant mutations.
Debounced Saves: Batch rapid changes (e.g., inline editing) into a 1‑second debounce before writing to storage.
Memory Management: Implement a dispose() pattern for modals/bottom sheets to remove event listeners and DOM nodes.
5.3 Service Worker / PWA

Inline a service worker script (registered via navigator.serviceWorker.register(blobURL)) that caches the index.html shell and intercepts fetch requests to serve from cache when offline.
Offline page: Show a banner "Working Offline — Changes will sync when reconnected".
Background sync simulation: Queue save operations; when online, replay them.

7. SECURITY, ACCESSIBILITY & POLISH

7.1 Simulated Security

Hashing: Use crypto.subtle.digest('SHA-256') with a per-user salt stored in the user record. For simulation speed, you may use a simplified HMAC.
Session: sessionStorage token (random 32‑char string) validated on every route change. Expires after 8 hours of inactivity.
PIN Lock: If enabled, blur the entire app with an overlay <div class="pin-overlay"> requiring 4‑6 digit PIN to dismiss. PIN is SHA‑256 hashed.
Brute force: After 5 failed login attempts, enforce a 30‑second lockout (timestamp in localStorage).
Field‑level permissions: If Viewer role, render inputs as disabled with opacity: 0.7 and no edit buttons. If Bookkeeper, hide "Delete Company" and "Manage Users" menu items entirely.
Sensitive data masking: Optionally mask bank account numbers, SSN/Tax ID in UI (***-**-1234) unless user clicks reveal.
7.2 Accessibility (WCAG 2.1 AA)

Focus management: Trap focus inside modals/bottom sheets (cycle Tab through focusable elements). Return focus to trigger on close.
ARIA: All custom components must have correct roles:
Dropdown: role="combobox", aria-expanded, aria-controls, aria-activedescendant.
Tables: role="table", row, cell, columnheader. Sortable headers announce state via aria-sort.
Alerts: Live regions (aria-live="polite") for toast notifications.
Screen reader: All icons must have aria-hidden="true" + accompanying text or aria-label. Currency amounts read as "$1,234.56" not "1234.56".
Keyboard: Every action reachable without mouse. Skip to main content link on first Tab.
Color contrast: All text meets 4.5:1 ratio. Do not rely on color alone for status — use icons + text.
Motion: Respect prefers-reduced-motion — disable animations, use instant transitions.
7.3 Dark Mode

Toggle in settings or via Ctrl+Shift+D.
Use data-theme="dark" on <html> and CSS variables that swap.
Images/attachments: Add subtle brightness(0.95) in dark mode to reduce eye strain.
Charts: Adjust grid lines to rgba(255,255,255,0.1), text to dm-text-secondary.
7.4 Micro‑interactions

Buttons: transition: all 0.15s ease.
Modals: Enter opacity 0→1, scale(0.96)→1, duration 200ms, easing cubic-bezier(0.16,1,0.3,1). Exit reverse, 150ms.
Bottom sheets: Enter translateY(100%)→0, exit reverse. Backdrop fades.

10. FINAL CODING MANDATES FOR THE AI AGENT

No External Dependencies: Everything must be contained in index.html. Inline all fonts as system font stack. Inline SVG icons (create a sprite sheet in a hidden <svg> block with <symbol> definitions, referenced via <use href="#icon-name">).
No Frameworks: Pure vanilla JavaScript (ES2020+). No React, Vue, Angular, jQuery, Bootstrap, Tailwind CDN. You may replicate a utility CSS approach with ~200 lines of atomic classes if needed, but prefer semantic BEM-style classes.
State Management: Use a single global AppState object with Proxy or explicit getter/setter methods that trigger render() debounces. Example: AppState.set('activeCompany', id) → persists → updates UI.
Routing: Hash-based routing (#/dashboard, #/transactions, #/reports/profit-loss). popstate listener updates the main view without page reload.
Rendering: Use a lightweight html tagged template literal function that sanitizes inputs (escape HTML). Batch DOM updates using DocumentFragment.
Date Handling: Use native Date with helper wrappers. Implement formatDate(), parseDate(), addDays(), startOfMonth(), etc. Respect user's dateFormat setting.
Number/Currency: Use Intl.NumberFormat with locale detection. For input fields, allow only digits, one decimal separator, and two decimal places. Display negative numbers in parentheses for accounting: (1,234.56).
Form Validation: Every form must validate before submit. Show inline errors below fields in accent-danger color. Shake animation (translateX keyframes) on submit if invalid.
Undo/Redo: Maintain an actionStack (max 50 deep) with inverse operations. Ctrl+Z / Ctrl+Shift+Z support.
Error Boundaries: Wrap all render calls in try/catch. If error, show a fallback UI: "Something went wrong" with "Reload App" button and error details in a collapsible <pre>.
Mobile Performance: Use touch-action: manipulation on buttons. Use passive: true on scroll listeners. Avoid setState on every scroll event; throttle to 100ms.
Testing Data: Include a generateSampleData() function that populates realistic 2-year transactional history, 20 customers, 15 vendors, 50 products, and 3 bank accounts. This is essential for the demo feel.
